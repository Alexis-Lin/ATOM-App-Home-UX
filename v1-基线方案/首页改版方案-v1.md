# ATOM App 首页改版方案说明

> 状态:方案草稿 v1 · 2026-06-08 · 发起人:Alex
> 配套材料:`交互原型.html`(浏览器打开,可切换新/老用户状态、点击设备条预览异常态)、三张状态截图

---

## 一、背景与问题诊断

现版首页(见线上 App)存在四个核心问题:

| # | 问题 | 表现 |
|---|------|------|
| 1 | 空状态是"死区" | My Schedule 的咖啡杯插画和 Custom Templates 的 "No Templates" 占近半屏且不可操作;CTA(Generate banner)与空状态在视觉上割裂 |
| 2 | 设备卡占位过大 | 连接正常时"已连接"只是状态确认,不值得占首屏约 1/4 |
| 3 | 模块缺失 | 无教程引导、无运营位、无数据回顾、无连续打卡,新用户不会用设备,老用户缺少回访价值 |
| 4 | 首页静态 | 新老用户看到完全相同的页面,两类人群的核心诉求差异很大 |

## 二、改版原则

1. **空状态 → 行动卡**:任何空状态都必须转化为带 CTA 的引导,或直接折叠隐藏。
2. **状态驱动**:首页按用户生命周期(新/老)和设备状态动态渲染,而非固定模块堆叠。
3. **优先级分层**:今天该做什么 > 运营活动 > 内容分发。运营内容不得高于核心训练动线。
4. **常驻的是入口,不是内容**:持续性信息收进固定入口,首页展示位保持新鲜轮换。

## 三、页面信息架构

```
顶部问候 + 铃铛(常驻活动/消息入口,带红点)
├─ 设备状态条(状态驱动:正常压扁 / 异常展开)
├─ 强时效公告条(仅重大事件出现,可关闭)
├─ 【动态区】新用户:生成计划英雄卡 + 新手任务清单 + 训练答疑 Tips
│           老用户:今日训练卡 + 周历打卡 + 本周数据条 + 推荐 Tips
├─ 官方活动轮播卡位(常驻展示位)
├─ 创建自定义模板(空状态折叠为单行入口)
├─ 精选训练(横滑)
└─ 精选计划
```

## 四、模块规则说明

### 1. 设备状态条(状态驱动)
- **正常态**:单行压扁 — 设备名 + 连接绿点 + 电量 + 设置入口。
- **异常态**(断连 / 低电量 / 固件升级):自动展开为警示大卡,带原因说明和操作按钮(如"重新连接 / 排查帮助")。
- 原则:正常时是背景信息,异常时才升级为首要信息。**不采用常态加高**。

### 2. 动态主区(按用户状态二选一)

**新用户(未生成计划 / 未完成首训):**
- *英雄卡*:替代原空状态。主 CTA"立即生成"(AI 问答生成计划),次 CTA"浏览预置计划"。
- *新手任务清单*(5 步,带进度条,全部完成后整个模块消失):
  1. 连接 Atom 设备
  2. 完善个人资料(昵称 / 身高体重)
  3. 填写训练偏好问卷(30 秒:目标 / 水平 / 器械)
  4. 学会摆放设备(2 分钟视频)
  5. 完成首次训练(推荐 10 分钟入门课)
  - ⚠️ 建议:②③ 优先放注册流程内收集,首页清单只做未完成项的兜底。清单越短完成率越高。
- *训练答疑 Tips*(横滑):只放"练起来之后才遇到"的问题(出框提示、计数不准、光线)。**与任务清单按时间线切分,不重复**:首训前必须会的 → 任务清单;训练中的问题 → Tips。

**老用户(有进行中计划):**
- *今日训练卡*(黑卡,最高优先):课程名 + 时长/动作数/部位 + 周进度 + 连续打卡天数 + "开始训练"。
- *周历打卡条*:7 天视图,完成日打勾。
- *本周数据条*:训练次数 / 时长 / 千卡。
- *推荐 Tips*:新功能介绍、月度报告等。

### 3. 运营信息三层结构
| 层 | 位置 | 性质 | 内容示例 |
|----|------|------|----------|
| 常驻入口 | 顶部铃铛(红点) | 永远在 | 活动中心 / 消息中心 |
| 常驻展示位 | "官方活动"轮播卡位(今日行动之下、精选之上) | 高度固定,内容轮换 | 挑战赛(倒计时+参与人数)、直播课(预约) |
| 强时效公告 | 顶部公告条 | 仅重大事件,可关闭 | 版本发布、重大活动开幕 |

- 防"盲区"手段:卡片轮换 + 倒计时 / 参与人数等动态信息;公告条保持稀缺性。

### 4. 自定义模板
- 空状态不再独占区块,折叠为单行"+ 创建自定义模板"入口。
- 已有模板时可展开为横滑卡(本期未出样式,待设计)。

## 五、开放问题(待团队讨论)

1. 新手任务 ②③(资料/偏好问卷)放注册流程还是首页清单?对注册流失率的影响需评估。
2. 老用户"今日休息日"的主卡样式(本方案未覆盖):建议显示恢复建议或拉伸课,而非空白。
3. 官方活动卡位无活动可投放时的降级策略:隐藏整个区块,还是投放常青内容?
4. 周历打卡与 History 页的数据口径需对齐。
5. 铃铛 = 活动中心还是统一消息中心(含系统通知)?需要和推送策略一起定。
6. 模板有内容时的卡片样式、以及模板与"生成计划"动线的关系。
